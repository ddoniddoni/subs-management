# Step 11 쿠폰 운영 화면 실행 계획

## 목표

- `/admin/coupons`를 플레이스홀더에서 실제 운영 워크플로우 화면으로 전환한다.
- 쿠폰 검색, 상태 필터, 정렬, 페이지네이션을 제공해 운영자가 쿠폰 풀을 빠르게 관리할 수 있게 한다.
- 신규 쿠폰 발급과 기존 쿠폰 회수 흐름에 확인 절차와 처리 이력을 붙여 운영 안전성을 높인다.

## 가정

- 실제 서버 API 없이 기존 목업 데이터와 클라이언트 상태만으로 쿠폰 운영 흐름을 구성한다.
- 쿠폰 발급은 관리자 입력을 기반으로 목업 리스트에 즉시 추가하는 방식으로 처리한다.
- 회수 액션은 이미 만료된 쿠폰이 아닌 건에 대해서만 가능하게 유지한다.

## 범위

- `/admin/coupons` 실화면 구현
- 쿠폰 목록용 파생 helper 추가
- 검색, 상태 필터, 정렬, 페이지네이션 추가
- 신규 쿠폰 발급 폼과 회수 확인 플로우 추가
- 처리 이력과 피드백 배너 추가
- 관련 테스트 추가

## 구현 단계

1. 쿠폰 운영 helper 작성
   - 고객 연결 정보, 검색/필터/정렬/페이지네이션, 요약 통계를 조합한다.
2. 쿠폰 운영 workbench 구현
   - KPI 요약
   - 운영 테이블
   - 발급 폼
   - 회수 확인 패널
   - 처리 이력
3. 페이지 연결
   - `/admin/coupons`에서 플레이스홀더를 제거하고 workbench 연결
4. 테스트 및 검증
   - helper 테스트
   - 발급/회수 시나리오 테스트
   - `npm.cmd run lint`
   - `npm.cmd run typecheck`
   - `npm.cmd run test`
   - `npm.cmd run build`

## 리스크

- 발급 폼이 과도하게 복잡해지면 화면이 무거워질 수 있다.
  - 대응: v1에서는 핵심 필드만 받는다.
- 검색/필터/정렬 로직이 발급/회수 후 즉시 일관되게 갱신되지 않을 수 있다.
  - 대응: 파생 로직을 helper로 분리하고 상태 변경 후 동일한 입력으로 다시 계산한다.
- 쿠폰 상태 변화와 활동 이력이 분리되어 보일 수 있다.
  - 대응: 처리 성공 시 피드백 배너와 activity feed를 동시에 갱신한다.

## 검증 방법

- 검색, 상태 필터, 정렬, 페이지네이션이 의도대로 동작하는지 확인한다.
- 신규 쿠폰 발급 후 목록, 요약 카드, 활동 이력에 즉시 반영되는지 확인한다.
- 쿠폰 회수 시 확인 절차를 거쳐 상태와 활동 이력이 반영되는지 확인한다.
