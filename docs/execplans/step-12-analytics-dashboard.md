# Step 12 분석 대시보드 실행 계획

## 목표

- `/admin/analytics`를 플레이스홀더에서 실제 운영 KPI와 추이 차트를 보여주는 화면으로 전환한다.
- 매출, 활성 고객, 실패 결제, 환불 대기, 이탈 위험 같은 핵심 지표를 운영 판단에 도움이 되는 방식으로 요약한다.
- 관리자 홈과 별도로, 추세와 분포를 확인할 수 있는 분석 전용 화면을 만든다.

## 가정

- 실제 서버 분석 API 없이 목업 `MetricSnapshot` 시계열과 현재 도메인 데이터를 조합해 분석 화면을 구성한다.
- 차트는 외부 라이브러리 없이 CSS 기반 바/라인 형태의 경량 시각화로 구현한다.
- 지표 계산은 helper에서 수행해 화면 컴포넌트는 읽기 중심으로 유지한다.

## 범위

- `metricSnapshots` 시계열 목업 추가
- 분석 helper 추가
- `/admin/analytics` 화면 구현
- 로딩, 빈 상태, 에러 상태 추가
- 관련 테스트 추가

## 구현 단계

1. 목업 지표 시계열 추가
   - 최근 6개 시점의 MRR, 활성 고객, 실패 결제, 환불 대기, churn 수치 정의
2. 분석 helper 작성
   - 현재 KPI
   - 직전 시점 대비 변화
   - 추이 차트용 데이터
   - 구독 상태/플랜/세그먼트 분포
   - 운영 리스크 큐 요약
3. 분석 화면 구현
   - KPI 카드
   - 추이 차트
   - 분포 카드
   - 운영 리스크 테이블
   - empty/error/loading 상태
4. 테스트 및 검증
   - helper 테스트
   - 주요 렌더링 테스트
   - `npm.cmd run lint`
   - `npm.cmd run typecheck`
   - `npm.cmd run test`
   - `npm.cmd run build`

## 리스크

- 차트가 장식적으로만 보일 수 있다.
  - 대응: 수치와 변화량을 같이 표기하고 운영 의미가 분명한 지표만 선택한다.
- 시계열 목업이 현재 KPI와 어긋나 보일 수 있다.
  - 대응: 현재 스냅샷을 마지막 값으로 맞추고 이전 값만 완만하게 조정한다.
- 화면 정보량이 과도해질 수 있다.
  - 대응: 상단 KPI, 중단 추이, 하단 분포/리스크 순으로 구역을 분리한다.

## 검증 방법

- KPI 카드가 현재 시점과 직전 시점 대비 변화를 올바르게 보여주는지 확인한다.
- 추이 차트와 분포 영역이 비어 있지 않고 의미 있는 값으로 채워지는지 확인한다.
- 시계열이 비어 있을 때 빈 상태나 에러 상태가 올바르게 보이는지 확인한다.
