# 실행 계획 - Bootstrap Step 15 고객 계정 센터

## 목적

고객 획득 흐름까지 완성했으니, 이번 단계에서는 고객이 결제 후 실제로 머무는 계정 구간을 다듬습니다. `내 구독`과 `결제 내역`을 richer account center로 바꿔 고객이 상태를 이해하고, 문제가 생겼을 때 무엇을 보면 되는지 바로 알 수 있게 만듭니다.

## 이번 단계에서 할 일

- 고객 계정 snapshot/helper 추가
- `/app/subscription` 고도화
- `/app/billing` 고도화
- billing 필터/정렬 인터랙션 추가
- 관련 테스트 추가

## 이번 단계에서 하지 않을 일

- 실제 구독 변경 / 해지 처리
- 실제 카드 변경
- 실제 영수증 다운로드
- 고객 인증 / 계정 설정

## 우선 대상 화면

### 1. `/app/subscription`
- 현재 상태 요약
- 다음 청구 안내
- 할인/쿠폰 요약
- 최근 구독 타임라인
- 추천 액션

### 2. `/app/billing`
- 결제 건강도 카드
- 상태 필터 / 정렬
- 청구 이력 테이블
- 실패 결제 / 환불 안내 패널

## 구현 방향

### 1. 고객 시점의 메시지
- 운영자가 보는 raw 상태값보다, 고객이 이해하기 쉬운 설명과 다음 행동 중심으로 정리한다.

### 2. helper 중심 조합
- invoices, payments, refunds, coupons, subscriptions를 customerId 기준으로 조합하는 helper를 만든다.

### 3. 필요한 상호작용만 클라이언트
- billing 필터/정렬 같은 인터랙션만 클라이언트 컴포넌트로 두고, 데이터 조합은 서버/순수 helper에서 끝낸다.

### 4. 상태 명시
- 고객 페이지도 empty / error / success를 명확히 보여주고, 결제 실패 같은 warning 상태를 숨기지 않는다.

## 리스크

### 리스크 1
고객이 볼 필요 없는 운영자 관점 정보가 섞일 수 있다.

대응
- 고객이 이해할 문장, 상태, 액션만 노출하고 운영 로그는 직접 노출하지 않는다.

### 리스크 2
billing 테이블 인터랙션이 과해 보일 수 있다.

대응
- 상태 필터와 정렬처럼 핵심적인 최소 인터랙션만 넣는다.

### 리스크 3
현재 목업 데이터가 적어 빈약하게 보일 수 있다.

대응
- 요약 카드와 안내 패널을 추가해 정보 밀도를 보강한다.

## 완료 기준

- `/app/subscription`과 `/app/billing`이 richer customer account center로 동작한다.
- billing 필터/정렬이 동작한다.
- 관련 테스트가 추가되고 통과한다.
- `npm.cmd run lint`
- `npm.cmd run typecheck`
- `npm.cmd run test`
- `npm.cmd run build`
