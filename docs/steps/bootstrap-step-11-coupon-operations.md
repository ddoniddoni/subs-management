# 실행 계획 - Bootstrap Step 11 쿠폰 운영 화면 심화

## 목적

Step 10에서 결제 상세 추적까지 연결했다면, 이번 단계에서는 운영자 대시보드의 남은 핵심 영역 중 하나인 쿠폰 관리 화면을 실제 업무 흐름에 맞게 채운다. 단순 목록이 아니라 발급, 상태 관리, 회수, 고객 연결, 처리 이력을 갖춘 운영 화면으로 바꿔 관리자 콘솔 완성도를 높인다.

## 이번 단계에서 할 일

- `/admin/coupons` 플레이스홀더 제거
- 쿠폰 목록, 검색, 상태 필터, 정렬, 페이지네이션 구현
- 신규 쿠폰 발급 폼 추가
- 회수 확인 플로우와 처리 피드백 추가
- 쿠폰 처리 이력 표시
- 관련 테스트 추가

## 이번 단계에서 하지 않을 일

- 쿠폰 상세 페이지 추가
- 서버 저장 또는 실제 API 연동
- 복수 쿠폰 벌크 액션
- 프로모션 규칙 엔진 수준의 복잡한 정책 UI

## 우선 대상 화면

### 1. `/admin/coupons`
- 쿠폰 KPI 요약
- 운영 테이블
- 발급 폼
- 회수 확인 패널
- 처리 이력

## 구현 방향

### 1. 운영 테이블 우선
- 관리자 테이블 규칙에 맞춰 검색, 필터, 정렬, 페이지네이션을 먼저 제공한다.

### 2. 위험 액션 보호
- 쿠폰 회수는 별도 확인 단계를 거쳐 실행하고 성공/실패 피드백을 명시한다.

### 3. 발급 흐름 단순화
- 고객, 제목, 코드, 할인 유형/값, 만료일 정도의 핵심 필드만 받아 빠르게 시연 가능한 운영 흐름을 만든다.

### 4. 활동 이력 연결
- 기존 감사 이벤트와 이번 세션의 로컬 처리 이력을 한 곳에서 함께 보여준다.

## 리스크

### 리스크 1
한 화면에 테이블과 폼, 액션 패널을 모두 넣으면 밀도가 높아질 수 있다.

대응
- 상단은 요약 카드, 중간은 테이블, 하단은 발급/회수와 이력 영역으로 구분한다.

### 리스크 2
목업 데이터 기준 쿠폰 수가 적어 페이지네이션 의미가 약할 수 있다.

대응
- 발급 액션으로 데이터가 늘어나도 자연스럽게 동작하는 구조를 먼저 만든다.

### 리스크 3
쿠폰 상태 규칙이 모호해 보일 수 있다.

대응
- active, scheduled, revoked, expired 상태를 명시적으로 보여주고 회수 가능 상태를 UI에서 분리한다.

## 완료 기준

- `/admin/coupons`가 실제 운영 화면으로 동작한다.
- 검색, 필터, 정렬, 페이지네이션이 제공된다.
- 쿠폰 발급과 회수 흐름에 확인 절차와 피드백이 있다.
- 처리 이력이 화면에 보인다.
- 관련 테스트가 추가되고 통과한다.
- `npm.cmd run lint`
- `npm.cmd run typecheck`
- `npm.cmd run test`
- `npm.cmd run build`
