# 실행 계획 - Bootstrap Step 12 분석 대시보드 심화

## 목적

Step 11에서 쿠폰 운영 화면까지 채웠다면, 이번 단계에서는 관리자 콘솔의 분석 영역을 실제 KPI와 차트 중심 화면으로 심화한다. 운영자는 목록 화면에서 개별 건을 처리할 뿐 아니라 전체 흐름을 한눈에 봐야 하므로, `/admin/analytics`에서 매출, 고객, 실패 결제, 환불 대기, 위험 신호를 함께 읽을 수 있게 만든다.

## 이번 단계에서 할 일

- `/admin/analytics` 플레이스홀더 제거
- metric snapshot 시계열 추가
- KPI 카드, 추이 차트, 분포 섹션, 운영 리스크 요약 구현
- loading / empty / error 상태 추가
- 관련 테스트 추가

## 이번 단계에서 하지 않을 일

- 실시간 데이터 갱신
- 차트 라이브러리 도입
- CSV 내보내기
- 고급 필터 패널

## 우선 대상 화면

### 1. `/admin/analytics`
- KPI 카드
- MRR / 활성 고객 / 실패 결제 추이
- 구독 상태/플랜/고객 세그먼트 분포
- 운영 리스크 테이블

## 구현 방향

### 1. KPI와 차트의 역할 분리
- 상단 KPI는 현재 상태와 전주 대비 변화량을, 차트는 최근 추세를 보여주는 역할로 구분한다.

### 2. 운영 맥락 유지
- 단순 숫자 대신 실패 결제, 환불 대기, 만료 임박 쿠폰 같은 운영 신호를 함께 보여준다.

### 3. 경량 시각화
- 외부 차트 라이브러리 없이 CSS 기반 시각화로 구현해 현재 코드베이스와 무게를 맞춘다.

### 4. 예외 상태 명시
- 스냅샷이 없거나 핵심 데이터가 비어 있으면 빈 상태 또는 에러 상태를 직접 보여준다.

## 리스크

### 리스크 1
차트가 시각적으로만 그럴듯하고 실제 해석 포인트가 약할 수 있다.

대응
- 각 섹션에 수치 요약과 운영 해석 문구를 함께 둔다.

### 리스크 2
홈 대시보드와 분석 페이지가 중복돼 보일 수 있다.

대응
- 홈은 즉시 대응 중심, 분석은 추세와 분포 중심으로 역할을 나눈다.

### 리스크 3
목업 시계열이 현재 데이터와 충돌해 보일 수 있다.

대응
- 가장 최신 시점은 현재 metric snapshot에 맞추고 이전 시점만 보간한다.

## 완료 기준

- `/admin/analytics`가 실제 분석 화면으로 동작한다.
- KPI, 추이, 분포, 리스크 영역이 모두 채워진다.
- loading / empty / error 상태가 포함된다.
- 관련 테스트가 추가되고 통과한다.
- `npm.cmd run lint`
- `npm.cmd run typecheck`
- `npm.cmd run test`
- `npm.cmd run build`
