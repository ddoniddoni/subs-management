# 실행 계획 - Bootstrap Step 16 관리자 커맨드 센터

## 목적

지금까지 각 관리자 화면은 대부분 완성됐지만, `/admin` 홈은 아직 단순한 요약 수준입니다. 이번 단계에서는 운영자가 로그인하자마자 “지금 무엇을 먼저 처리해야 하는가”를 볼 수 있는 커맨드 센터로 홈 화면을 강화합니다.

## 이번 단계에서 할 일

- `/admin` 홈 command center 구현
- KPI 카드 정리
- 우선 대응 큐 구현
- 빠른 진입 카드 구현
- 최근 감사 활동 피드 연결
- loading 상태와 관련 테스트 추가

## 이번 단계에서 하지 않을 일

- 실시간 polling
- 차트 라이브러리 추가
- 새로운 관리자 라우트 추가
- action-level inline 처리

## 우선 대상 화면

### 1. `/admin`
- 운영 KPI
- 오늘의 우선 대응 큐
- 고객/구독 watchlist
- 빠른 진입 카드
- 최근 활동 피드

## 구현 방향

### 1. 분석보다 실행 중심
- analytics가 추세와 분포를 담당하므로, 홈은 바로 처리할 큐와 이동 링크를 중심으로 구성한다.

### 2. helper 중심 조합
- 결제, 환불, 구독, 쿠폰, 감사 로그를 helper 한 곳에서 조합해 page는 snapshot 렌더링만 하게 만든다.

### 3. 운영 밀도 확보
- KPI 카드만으로 끝내지 않고, 실제 운영자가 다음으로 눌러야 할 화면까지 함께 보여준다.

### 4. 로딩/비어 있음 대비
- 목업 데이터가 비어도 안전하게 fallback을 보여주도록 한다.

## 리스크

### 리스크 1
홈과 analytics의 역할이 중복돼 보일 수 있다.

대응
- 홈은 queue와 quick access, analytics는 trend와 distribution으로 역할을 구분한다.

### 리스크 2
데이터가 적어서 watchlist가 빈약해 보일 수 있다.

대응
- 여러 도메인 신호를 한 큐로 묶어 밀도를 높인다.

### 리스크 3
한 화면에 정보가 너무 많아질 수 있다.

대응
- 상단 KPI, 중단 큐, 하단 진입/활동 두 구획으로 정리한다.

## 완료 기준

- `/admin`이 command center 형태로 동작한다.
- 우선 대응 큐와 빠른 진입 링크가 정상 연결된다.
- 관련 테스트가 추가되고 통과한다.
- `npm.cmd run lint`
- `npm.cmd run typecheck`
- `npm.cmd run test`
- `npm.cmd run build`
